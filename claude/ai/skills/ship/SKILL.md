Wrap up the current branch: $ARGUMENTS

1. Run in Bash: `REVIEW_CALLER=ship codex-review recheck <base>` (base = the branch this one was cut from; if unsure, omit it and the script uses the repo's default branch). It reuses the last review of this branch, usually the loop's Stage 4 or 5. Nothing changed since that review: it prints that review again and asks no model (`REVIEWER: stamp …`). Something changed: it reviews only the changes and checks the earlier findings. No usable earlier review: a full review. (10–17 Oct 2026: 9 of 11 ship reviews came right after a loop review of the same work.) If it exits 75, delegate the review to the `reviewer` agent and flag it as same-vendor, and repeat in your report the line saying when each lane is usable again. Run it in the background and do not poll it (every check is a full main-model turn): Claude Code reports when it exits, and it ends by itself within 35 minutes (limits are caught in seconds, silence after 5–10 minutes). If no exit report has come after 36 minutes, kill it and treat it as exit 75.
2. A SHIP needs no fix: list its P2/P3 notes in the report. Otherwise fix every P0 and P1 finding you agree with, and the P2s that are a one-line fix. List the ones you rejected and why. If a finding is a mistake that will recur in that folder, propose one line for the nearest nested `AGENTS.md` gotchas file (add it only on my yes).
3. If step 2 changed code, re-run `codex-review recheck <base>` once. Then run the tests and the build yourself, once; do not rely on the reviewer for that. A test run that reports zero tests, or stops before it loads the test files, is a failure.
4. Commit with a message that summarises the change and ends with the verdict line. Because a review just ran, prefix the commit so the pre-commit hook doesn't run a second one: `AI_LOOP_SKIP_REVIEW=1 git commit -m "..."`. Do not push or merge unless I say so.
5. Review notes: `codex-review` keeps this branch's open findings in `docs/tasks/review-notes/<branch>.md` (0.18.0). Leave the open ones there and commit the file with the branch, so they stay visible; name them in the report. When the file says no open findings, archive it with the rest.
6. Archive what this branch finished: `git mv` its spec from `docs/specs/` and every `docs/tasks/` file of the same work (`<slug>-*.md` and the files its spec names: plans, run notes, QA notes, handoffs) to `docs/archive/` under the same names (a run note that cites the spec moves with it: do not only fix its path; keep a file only while it holds an open follow-up, and name it in the report), add one line per file to `docs/archive/README.md` (file, what shipped, month; create the file with a table if missing), and update any path that cites them (`git grep <file name>`). Then list anything else in `docs/specs/` or `docs/tasks/` that looks finished or abandoned (its work merged, its "Done means" met, or untouched for a month) and move those only on my yes. Commit the moves separately with `AI_LOOP_SKIP_REVIEW=1`.
